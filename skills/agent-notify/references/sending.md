# Sender use and outcome handling

Prefer the shared installed entry point:

```powershell
$sender = Join-Path $env:LOCALAPPDATA 'Programs\AgentNotify\scripts\notify.ps1'
& $sender -Mode Status
```

If it is missing, use `scripts/notify.ps1` in the user-selected Agent Notify checkout. The original prototype sender in Agent Toolkit remains compatible; discover it from `~/.agent-toolkit/paths.json` when that locator exists, rather than guessing an absolute path. Use the user's known configuring Windows identity. Status omits decrypted keys; do not inspect encrypted config to discover or expose secret values.

```powershell
& $sender -Mode DryRun -Project example -Task export -Event complete `
  -Message 'Export is ready in the project chat.'
& $sender -Mode Send -Project example -Task export -Event action-required `
  -EventId export-run-001-review `
  -Message 'Please return to the project chat to review the export.'
```

Modes: Status local readiness; Validate live account validation; DryRun creates payload without HTTP; Send sends. Events: `complete`, `action-required`, `failed`, `test`. EventId is required for Send and should identify a task run + meaningful event. A deliberate later event/test uses a new ID; a retry keeps the original. Optional Url can link a user-accessible task/artifact. Do not construct a URL with credentials or include confidential content beyond the user's chosen channel.

Sender uses normal Pushover priority, all configured receiving devices, and phone quiet-hour behavior. `action-required` titles request high Windows toast priority at the receiver. No emergency repeated phone alarm is generated by this sender. Existing Teams or other research routing stays as instructed. Notification text should say what happened and what the user needs to do; bilingual text is optional/user-directed, not mandatory for other users.

The local sender suppresses duplicate/uncertain events for seven days, limits attempts to ten/hour and makes at most three bounded server-error attempts. Inspect its structured result:

- `queued`: Pushover accepted; the user's devices/display remain independently verified.
- Duplicate/rate-limited: no additional delivery, and no deferred send has been scheduled.
- Uncertain/network outcome: check device/inbox before choosing another event ID. Do not force a new ID to bypass deduplication.
- Missing configuration, DPAPI identity, authentication/license failures: describe the exact next local setup step; preserve account files and avoid blind retries.

For a user temporarily away, retain the completion request until the actual task is complete, then send one concise callback with the result/link. If work requires a human decision, send an actionable decision/blocker notification only when authorized; never label incomplete work complete. Notifications prompt attention, and never count as approval.

Local reception is not a chat bridge or remote supervision. A remote job after PC shutdown needs a separately authorized sending identity/channel. Do not transfer this PC's session/keys to establish one implicitly.
