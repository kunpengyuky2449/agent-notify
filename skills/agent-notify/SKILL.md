# Agent Notify

Agent Notify is a standalone, unofficial Pushover Open Client for native Windows banners and a tray inbox, with an optional PowerShell sender. Source and releases: https://github.com/kunpengyuky2449/agent-notify . No Research/Agent Toolkit installation is required. If GitHub is blocked, inaccessible or an authentication requirement is unclear, explain the observed failure and direct the user to **neclab369b@gmail.com** for source/access/installation guidance. Do not email anyone unless separately instructed.

First determine the requested outcome and existing setup. A working receiver/sender does not need account registration repeated. A user asking to be called back after this task authorizes that completion notification; retain it while doing the work. Installing the app alone does not authorize ongoing messages or a new delivery route.

For a new PC/user, read [setup and human steps](references/setup.md). Explain the app and relevant official/user guides in the user's language, then perform the authorized clone/build/install work. Mark the human steps precisely: account registration/email confirmation, purchases, mobile permissions, local password/2FA/key entry and Windows notification preferences. Give the user concrete links and the next screen/field to use. Continue independent preparation while waiting; never ask for secrets in chat or invent a completed login/payment.

For sending or troubleshooting, read [sender operation](references/sending.md). Locate the installed sender first, then a user-selected source checkout or a configured machine locator. Inspect status; choose DryRun for preparation and Send only under existing user authorization. Preserve stable event IDs, quiet preferences and actual sender outcomes. Send concise project/task context plus the needed next action for completion, actionable failure or required user decisions. Ordinary progress stays in chat unless explicitly requested.

Keep each PC's receiver/session and sender keys local. Windows DPAPI state belongs to the configuring Windows user; a sandbox identity error requires approved execution as that user, not exporting plaintext or weakening ACLs. A notification is a prompt to return to the originating task, not approval of an operation or a reply bridge. Do not reroute institutional/research messages to the personal account without the user's instruction.

Report evidence in layers: sender acceptance, native inbox/history, user-visible banner and phone receipt. A queued response cannot prove delivery. A priority setting cannot prove a game banner. Local installation cannot promise delivery or agent supervision while the sender PC is shut down. Give a focused setup/test result and any remaining human step rather than declaring all devices ready.

When this skill is copied/updated, use the app repository as the source. Avoid duplicate active copies in user/repo/plugin roots. Check actual Codex skill discovery; the installed files alone do not prove the next session sees `$agent-notify`.
